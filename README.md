# incr

An instrumented incremental computation engine for Rust, built as a research and learning project.

You mark data as inputs and write pure functions as queries. `incr` caches each result and re-runs only what changed when an input changes.

The narrow question: when does the simplest possible design pay off, and where does it break? current baseline: one global revision, pure queries, automatic `Eq` cutoff, no durability, persistence, or eviction. Every deferred feature is a hypothesis. I'll change the plan as this teaches me something.

I started because I like how Salsa and rust-analyzer work, self-adjusting computation is a good place to learn, and it made me curious.

See `docs/design.md` for the design.

## How it works

```
inputs (InputMap, per-key revision)
     |
     v
queries (pure fns, you write) -> typed memo tables { Arc<value>, verified_at, changed_at, deps }
     |
     v
caller asks query(k) -> if deps unchanged, return cached Arc; else recompute
```

- One `Revision`. `set_input` bumps it. A same-value set does not bump the key's `changed_at`.
- Memos store `verified_at` and `changed_at`. A read validates deps. Nothing changed: return the cache. A re-run with an equal value keeps `changed_at`, so parents skip theirs.
- `Db` owns dependency tracking. A query pushes a frame. Reads and nested queries record edges there, cache hits included.
- Values are `Arc<V>`. Cloning large ASTs is the hidden tax. Cutoff is a policy: `Eq` by default, fingerprint for large values.

One revision is the baseline. Early cutoff saves recomputation, not the validation walk. Durability is separate.

## What I decided

The v0.1 choices. Each one is a baseline.

- workload: generic pull engine plus a toy compiler. The first measured workload, not a hypothetical.
- revision: single `Revision`. Input-level equality stops no-op edits from bumping `changed_at`. Durability is deferred and measured.
- API: plain `Db` with `#[derive(incr::Db)]` and `#[query]` on an `impl` block or free functions. No query groups.
- inputs: `InputMap<K, V>` with per-key revisions and dependency identity. A bare `HashMap` is not enough.
- storage: typed per-query tables (`HashMap<K, Memo<V>>`) behind a registry, `Arc<V>` values, unbounded for v0.1.
- cutoff: a `Cutoff` trait, `Eq` by default. Fingerprint cutoff is an experiment.
- cycles: detect via stack, panic with the trace. Fallback and fixpoint later.
- threads: single threaded, snapshot parallelism later. Keep the seams.
- bounds: typed keys, `Arc<V>`, `V: 'static`. `Debug` is a debug feature. No interning.
- persistence: none. A research chapter, not a serde feature.
- correctness: from-scratch consistency plus work assertions.

## Quick look

Target shape. Macros land after the runtime and the first benchmark.

```rust
use incr::{InputMap, query};
use std::sync::Arc;

type FileId = u32;

#[derive(Default, incr::Db)]
struct MyDb {
    #[input]
    src: InputMap<FileId, Arc<str>>,
    memo: incr::MemoTable,
}

#[query]
impl MyDb {
    fn parse(&self, id: FileId) -> Arc<Vec<String>> {
        let words = self.src(id)
            .split_whitespace()
            .map(str::to_owned)
            .collect();
        Arc::new(words)
    }

    fn count_words(&self, id: FileId) -> usize {
        self.parse(id).len()
    }
}

fn main() {
    let mut db = MyDb::default();
    db.set_src(1, Arc::from("hello world"));
    assert_eq!(db.count_words(1), 2); // computes and caches

    db.set_src(1, Arc::from("hello world"));
    assert_eq!(db.count_words(1), 2); // same value: input changed_at stays

    db.set_src(1, Arc::from("hello incr"));
    assert_eq!(db.count_words(1), 2); // parse reruns, count_words may cut off
}
```
